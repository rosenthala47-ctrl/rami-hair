# מפת דרכים ליישום — Step by Step

> מסמך זה מפרק את הבנייה לשלבים מעשיים, ומסמן **בבירור** בכל שלב מה עושה ה-AI לבד ומה **דורש ממך** פעולה (בעיקר: פתיחת חשבונות, פרטי אשראי, ואישורי תקציב — כי אלה דברים שמבחינה חוקית/פיננסית **חייבים** להיעשות ע"י אדם).

מקרא: 🧑 = פעולה שרק אתה יכול לבצע | 🤖 = מבוצע ע"י סוכן/אוטומציה | ✅ = שער אישור (אתה מאשר, ה-AI מבצע)

---

## Phase 0 — יסודות (לפני שיש בכלל "מערכת")

זו הפעולה הכי חשובה: **בלי השלב הזה שום סוכן AI יכול להתחיל לעבוד**, כי כל הכלים דורשים חשבון עם אימות זהות/אמצעי תשלום שרק אתה יכול לספק.

| # | פעולה | מי מבצע |
|---|---|---|
| 1 | קביעת תקרת תקציב חודשית כוללת (למשל: $500 חודש ראשון) וסף אישור אוטומטי (למשל: "מתחת ל-$20 — הסוכן פשוט מבצע, לא שואל") | 🧑 |
| 2 | פתיחת חשבון Vercel (לאירוח ה-Next.js) + רכישת דומיין | 🧑 |
| 3 | פתיחת חשבון Stripe (סליקה) — דורש אימות זהות/עסק | 🧑 |
| 4 | הקמת אירוח ל-Medusa.js + מסד נתונים Postgres (Railway/Render) | 🧑 (או שאני מקים, בהנחייתך) |
| 5 | יצירת חשבון Anthropic API (Claude) לחיוב שימוש הסוכנים | 🧑 |
| 6 | פתיחת חשבון n8n (Cloud, או self-host על שרת קטן — נדון ב-Phase 1) | 🧑 |
| 7 | חשבון ספק: CJ Dropshipping / Zendrop / AliExpress | 🧑 |
| 8 | חשבון Klaviyo/Omnisend (יש תוכנית חינמית להתחלה) | 🧑 |
| 9 | Meta Business Manager + חשבון פרסום + כרטיס אשראי לחיוב מודעות | 🧑 |
| 10 | חשבון TikTok Ads Manager | 🧑 |
| 11 | בוט טלגרם (BotFather — 2 דקות) עבור ה-Approval Hub | 🧑 (טכני מינימלי, אפשר גם שאני אדריך שלב-שלב) |
| 12 | מסמכי משפט בסיסיים: תקנון, מדיניות פרטיות, מדיניות החזרות | 🤖 טיוטה + 🧑 אישור/בדיקה משפטית אם נדרש |

> ⚠️ זה השלב שבו **אתה** צריך לפעול קודם. ברגע שיש בידיך API keys וחשבונות פתוחים — כל השאר (Phase 1 ואילך) יכול להתבצע ע"י המערכת עם מינימום מגע ידיכם.

---

## Phase 1 — תשתית ליבה (שבוע 1-2)

- 🤖 הקמת פרויקט Next.js בסיסי + Medusa.js (קטלוג/עגלה/הזמנות) + חיבור Stripe — עמודי חובה (אודות, צור קשר, תקנון), הגדרות משלוח ומיסים, מבנה עיצוב ראשוני.
- 🤖 חיבור n8n לכל ה-API keys (Medusa, Claude, Klaviyo, Meta, ספק).
- 🤖 בניית ה-**Approval Hub** (בוט טלגרם + Airtable) — זה נבנה **ראשון**, לפני שאר הסוכנים, כי כולם תלויים בו.
- 🤖 בניית workflow של **סוכן המחקר והספקים** — הוא חוסם את כל השאר כי אי אפשר לבנות דף מוצר בלי מוצר.
- ✅ שער: אתה מקבל את דו״ח ההזדמנויות הראשון ובוחר 1-2 מוצרים לבדיקה ("hero products" — **לא** 50 מוצרים; דרופשיפינג מצליח מתחיל ממוצר אחד חזק).

---

## Phase 2 — מוצר והשקה (שבוע 2-3)

- 🤖 סוכן התוכן בונה דף מוצר מלא (תיאור, תמונות/פרומפטים, FAQ).
- 🤖 סוכן ה-SEO מגדיר מבנה URL, meta tags, מילות מפתח יעד.
- ✅ שער: אישור סופי לדף המוצר לפני שהחנות עולה לאוויר (בדיקת התאמת מותג/איכות).
- 🧑 **בדיקת הזמנת דוגמה** מהספק לוודא איכות פיזית של המוצר לפני מכירה המונית — זו הפעולה האנושית החשובה ביותר בכל התהליך, כי AI לא יכול למשש מוצר.
- 🤖 החנות עולה לאוויר עם 1-2 מוצרי דגל.

---

## Phase 3 — הפעלת שיווק (שבוע 3-4)

- 🤖 סוכן המייל מקים Flows: Welcome, עגלה נטושה, פוסט-רכישה.
- 🤖 סוכן התוכן מתחיל קצב פרסום אורגני יומי/שבועי (TikTok/Reels/Instagram).
- ✅ שער: אישור תקציב פרסום ראשוני (מומלץ $10-20/יום לבדיקה, לא יותר, בשבועות הראשונים).
- 🤖 הרצת קמפיין בדיקה ממומן (Meta + TikTok) עם 3-5 קריאייטיבים שונים במקביל.
- 🤖 סוכן ה-SEO מתחיל כתיבת תוכן בלוג לתנועה אורגנית ארוכת-טווח.

---

## Phase 4 — שירות לקוחות וסקייל (שבוע 4+)

- 🤖 סוכן שירות הלקוחות מופעל במצב **"טיוטה לאישור מלא"** — כל תשובה עוברת דרכך לפני שליחה, כדי לוודא טון ואיכות.
- 🤖 דו״ח שבועי אוטומטי מסוכן ה-SEO/אנליטיקס: תנועה, המרות, CAC, ROAS, LTV.
- ✅ שער שבועי קבוע: "לולאת החלטה" — אתה מקבל תמצית אחת (לא 5 דשבורדים) עם המלצה: להגדיל תקציב למוצר/קמפיין מנצח, לעצור מפסיד, או להוסיף מוצר חדש מה-pipeline של סוכן המחקר.
- 🤖 לאחר 2-3 שבועות של תוצאות יציבות: מעבר הדרגתי של שירות הלקוחות למצב "שליחה אוטומטית לפניות שגרתיות בלבד" (סטטוס הזמנה וכו׳), תלונות/החזרים עדיין עוברים אישור.

---

## Phase 5 — אופטימיזציה והרחבה (שוטף)

- 🤖 הוספת מוצרים נוספים מה-pipeline של סוכן המחקר בקצב מבוקר (לא להציף את החנות).
- 🧑 החלטה תקופתית: להעלות רמות אוטומציה נוספות (למשל לתת לסוכן השירות לאשר בעצמו החזרים מתחת לסכום נמוך).
- אופציונלי בהמשך: מעבר משכבת n8n workflow-based לשילוב **CrewAI/AutoGen** לתקשורת אוטונומית בין סוכנים (לדוגמה: סוכן המחקר "משוחח" ישירות עם סוכן התוכן בלי לעבור דרך regels קבועים ב-n8n) — רלוונטי ברגע שהתהליכים הוכחו ורוצים לצמצם עוד יותר את זמן התגובה בין גילוי מוצר לפרסום.
- אופציונלי: בניית לוח בקרה פנימי (dashboard) שמרכז במקום אחד את נתוני כל הסוכנים, מעל Medusa Admin API — כדי לצמצם עוד יותר את הצורך להיכנס לכלים נפרדים.

## טבלת ריכוז — נקודות התערבות אנושית

| תחום | מתי נדרש אדם | תדירות |
|---|---|---|
| פתיחת חשבונות/API keys | פעם אחת בהקמה | חד פעמי |
| סליקה ואימות עסקי/זהות | הקמה + חידושים תקופתיים | נדיר |
| אישור מוצר חדש לחנות | כל פעם שסוכן המחקר ממליץ | שבועי |
| אישור תקציב פרסום (הגדלה/קמפיין חדש) | כל שינוי תקציב מהותי | שוטף, לפי הצורך |
| תשלום לספקים מעל סף | כל תשלום גדול | לפי הצורך |
| בדיקת איכות מוצר פיזי | לפני השקת כל מוצר חדש | לכל מוצר חדש |
| תלונת לקוח/בקשת החזר כספי | תמיד בהתחלה, בהמשך רק מעל סכום סף | לפי הצורך |
| סקירה משפטית של תקנון/מדיניות | הקמה + שינויים מהותיים | נדיר |
| לולאת החלטה שבועית (סקירת ביצועים) | קבוע | שבועי |

**הצעד הראשון בפועל:** התחל מ-Phase 0, סעיפים 1-5 (תקציב, Vercel+דומיין, Stripe, אירוח Medusa, Anthropic API) — ברגע שאלה בידיך, אפשר להתחיל לבנות בפועל את החנות, ה-Approval Hub וסוכן המחקר.
